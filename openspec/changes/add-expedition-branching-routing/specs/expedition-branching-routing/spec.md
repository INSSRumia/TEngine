## ADDED Requirements

### Requirement: 远征节点 SHALL 支持节点级路由策略
系统 MUST 让远征节点显式声明自己的路由策略，并至少支持固定出口、按选项出口和按条件出口三种模式。

#### Scenario: 节点使用固定出口
- **WHEN** 某个节点被配置为固定出口模式
- **THEN** 该节点在结算后进入其声明的默认出口

#### Scenario: 节点按选项出口
- **WHEN** 某个节点被配置为按选项出口模式
- **THEN** 系统根据当前节点定义的 `OptionId -> TransitionId` 映射决定后续出口
- **AND** 不依赖 option index 推断出口

#### Scenario: 节点按条件出口
- **WHEN** 某个节点被配置为按条件出口模式
- **THEN** 系统根据当前远征黑板和节点条件选择满足条件的出口

### Requirement: 远征 SHALL 维护可被后续分支读取的黑板状态
系统 MUST 为一次远征维护统一的黑板状态，用于记录标记、道具、历史选择和计数器等可被后续节点读取的长期状态。

#### Scenario: 后续节点读取黑板状态
- **WHEN** 某个节点出口依赖玩家之前的选择或持有状态
- **THEN** 系统从远征黑板中读取对应状态
- **AND** 不要求通过遍历全部节点记录才能完成条件判断

### Requirement: 远征 SHALL 使用待执行节点队列推进实际流程
系统 MUST 让一次远征的实际推进由待执行节点队列决定，而不是仅靠固定索引递增。

#### Scenario: 队列决定下一个执行节点
- **WHEN** 当前节点结算完成
- **THEN** 系统根据路由策略与运行时变更更新待执行节点队列
- **AND** 下一个执行节点来自队列头部

### Requirement: 系统 SHALL 支持运行时动态插入节点
系统 MUST 支持在远征运行过程中向待执行节点队列插入新的事件或支线节点，以表达延迟回收和临时遭遇等设计。

#### Scenario: 前序选择触发后段插入事件
- **WHEN** 某个前序选择满足了后续插入条件
- **THEN** 系统可在远征后续流程中插入一个新的事件节点
- **AND** 不要求修改静态图配置本身

### Requirement: Event 内容与 Node 路由语义 SHALL 分离
系统 MUST 保持 Event 只定义内容与选项，Node 负责定义该次事件实例的出口语义。

#### Scenario: 同一 Event 在不同 Node 中复用
- **WHEN** 两个不同节点复用同一个 Event 模板
- **THEN** 它们可以拥有不同的出口策略和不同的选项路由映射
- **AND** 不要求复制新的 Event 模板才能表达不同流程语义
