## Context

当前远征已经具备 `PendingNodeQueue`、`CurrentNodeEntry` 和动态插队能力，可以支持主线推进与立即插入节点，但还缺少一种“延迟若干节点后再插入事件或战斗”的配置化表达。现有 `event / random_event / combat` 三类节点本身已经满足内容展示、随机抽取和战斗执行，不需要再引入新的节点大类；真正缺失的是一种能把“后果延迟触发”收敛进 Expedition Effect 的最小机制。

用户已经明确确认以下约束：
- 保留 `event`、`random_event`、`combat` 三类节点，不新增新的主节点类型。
- 随机事件池与 `random_event` 节点当前设计保持不变。
- 新能力通过一个 Expedition Effect 实现，而不是额外引入新的流程动作系统。
- 延迟计数使用 `1` 表示“下一个节点就是插入节点”，避免 `0` 带来的特殊处理歧义。
- 动态生成节点只允许是 `event` 或 `combat`，并且该临时节点不配置 `transition` 与 `option_routes`。

## Goals / Non-Goals

**Goals:**
- 为远征新增一个“延迟插入节点” Expedition Effect，支持在若干节点后插入一个临时 `event` 或 `combat` 节点。
- 在 `ExpeditionRunState` 中新增待插入列表，统一管理所有尚未到期的延迟插入请求。
- 明确 `1` 基计数语义，并保证其实现不需要为“当前节点是否计数”增加额外特判。
- 让动态生成节点在执行完成后默认回到原有待执行队列继续推进，不改写静态路线图。
- 保持当前 FSM、大部分 UI 入口和随机事件系统不变。
- 保持 `xlsx` 由用户手工修改，agent 仅负责 schema、代码和清单说明。

**Non-Goals:**
- 不在这次变更中新增 `random_event` 类型的临时插入节点。
- 不在这次变更中把静态 `Route` 改造成运行时可写图结构。
- 不在这次变更中重做现有 `ScheduleInsertionAfterNode` 机制的整体设计。
- 不在这次变更中引入战斗前置 action、encounter wrapper 或新的节点调度 DSL。

## Decisions

### 1. 延迟插入能力通过 Expedition Effect 暴露，而不是新增节点大类
- 选择：在远征 Effect 系统中新增一个专门的“延迟插入节点” Effect。
- 原因：该能力本质上是“当前节点结算后埋下一个未来后果”，天然属于节点结果的一部分；放进 Effect 可以直接复用现有事件选项与战斗胜负结算链路。
- 备选方案：
  - 新增新的节点类型：会扩大节点模型和 UI/FSM 分支面，不符合当前“少加机制”的目标。
  - 把行为硬编码在随机事件系统里：会让随机事件承担不属于自己的职责。

### 2. 延迟计数使用 1 基语义，并在每次节点结算结束时统一递减
- 选择：配置中的 `passed_node_count = 1` 表示“当前节点结算完成后，插入节点将成为下一个执行节点”；`2` 表示“再经过一个普通后续节点后插入”。
- 原因：这样可以把规则统一为“每次节点结算结束时，所有待插入项统一递减一次；减到 0 就立即插入”，不需要再为 `0` 是否代表“立刻生效”做额外特判。
- 备选方案：
  - 使用 `0` 表示“下一个节点”：需要跳过创建当轮的首次递减，容易出现偏一位错误。

### 3. 运行时使用 `LstPendingInsertNode` 保存待到期条目
- 选择：在 `ExpeditionRunState` 中新增列表，元素至少包含：
  - `PendingInsertInstId`
  - `RemainingPassedNodeCount`
  - `NodeType`
  - `Id`
  - `SourceNodeConfigId`
  - `Reason`
  - `CreateOrder` 或等价顺序信息
- 原因：该结构既要保存倒计时，也要保留调试信息和稳定顺序；列表天然适合表达“多个条目同位到期时按登记顺序处理”。
- 备选方案：
  - 使用字典：不适合表达顺序语义。
  - 直接提前把临时节点放进 `PendingNodeQueue`：无法表达“还要先经过若干节点”。

### 4. 到期后生成的是“运行时临时节点”，不是静态 Route 中已有节点
- 选择：Effect 只配置一个简单节点描述：
  - `node_type = event` 时，`id` 表示 `event_config_id`
  - `node_type = combat` 时，`id` 表示 `combat_encounter_config_id`
  运行时再根据该描述构造一个临时节点记录并插入队列。
- 原因：需求目标是“插入一个事件/战斗结果”，不是让策划先在主路线里预埋一个真正的 `RouteNode`；运行时临时节点更符合“支线后果”语义。
- 备选方案：
  - 只允许插入已有 `node_config_id`：会把大量一次性支线节点重新压回静态主图，违背需求初衷。

### 5. 临时节点的路由语义固定为隐式 `fixed_next`
- 选择：临时节点不配置 `transition`、`option_routes`。它执行完成后默认回到 `PendingNodeQueue` 中原本已存在的后续节点继续推进。
- 原因：这些节点的职责只是“插队执行一次额外事件或战斗”，不是重写主线路由图；如果还要求配置独立出口，会让临时节点和静态节点边界重新混乱。
- 备选方案：
  - 为临时节点继续配置完整 Transition：会让简单插队需求重新变得笨重。

### 6. 同位置多条目按登记顺序处理，但最终执行顺序以后登记者优先
- 选择：当多个条目在同一节点结算后一起到期时，系统按 `LstPendingInsertNode` 中的顺序依次做“插入队首”操作。
- 原因：这完全符合用户当前定义的期望结果：越靠后的条目越晚插入队首，因此越早执行。
- 备选方案：
  - 反向遍历后再插入：虽然也能实现目标，但不如“按登记顺序插入队首”直观。

### 7. 递减与到期插入放在当前节点结果结算阶段，与普通路由同轮完成
- 选择：在当前节点完成 Effect 结算后、真正进入下一节点前，统一处理 `LstPendingInsertNode` 的递减与到期插入。到期插入完成后，再继续后续主线节点排队。
- 原因：这样可以保证：
  - `passed_node_count = 1` 的条目在创建当轮就能插成“下一个节点”
  - 所有插队行为都在离开当前节点前固定下来，便于调试和记录
- 备选方案：
  - 推迟到进入下一节点前再处理：语义上可行，但更难在节点记录中解释“为什么当前节点结算后队列突然变化”。

## Risks / Trade-offs

- [Risk] `1` 基计数虽然避免了 `0` 特判，但其文字语义与“经过几个节点”存在直觉偏差  
  → Mitigation：在 schema 注释、design 和样例配置中明确写出“1 = 下一个节点插入，2 = 下下个节点插入”。

- [Risk] 临时节点不是静态 `RouteNode`，可能导致现有依赖 `GetNode(nodeConfigId)` 的代码无法直接复用  
  → Mitigation：为运行时临时节点提供清晰的数据承载方式，并在流程控制器中区分“静态节点解析”和“临时节点解析”。

- [Risk] 当前已有的动态插入机制与新的延迟插入 Effect 同时存在时，执行顺序可能让人困惑  
  → Mitigation：在实现中明确记录顺序日志，并统一在“节点结果结算阶段”处理所有插队来源。

- [Risk] 允许插入 `combat` 后，若战斗失败直接结束远征，可能让策划误以为后续排队节点仍会执行  
  → Mitigation：在 spec 中明确远征结束优先级高于任何剩余待执行节点。

- [Risk] schema 变更后需要补充 `xlsx` 字段与样例数据，但 agent 不能代改表  
  → Mitigation：在 tasks 中单独列出手工改表步骤，由用户完成后再进入实现阶段。

## Migration Plan

1. 为 Expedition Effect schema 新增延迟插入节点 Effect 配置，以及简单节点配置结构。
2. 在远征运行态新增 `LstPendingInsertNode` 或等价运行时结构。
3. 在流程控制器的节点结算阶段接入待插入项的递减、到期判断与队首插入。
4. 为运行时临时 `event` / `combat` 节点补充最小解析与执行支持。
5. 由用户手工调整相关 `xlsx` 表结构和样例数据，并重新生成 Luban 代码。
6. 验证以下关键场景：
   - `1` 表示下一个节点插入
   - `2` 表示下下个节点插入
   - 多条目同位到期时后登记者先执行
   - 临时 `event` 与临时 `combat` 节点执行后能回到原流程
   - 战斗失败时远征正确终止

## Open Questions

- 当前没有必须阻塞 proposal 阶段的开放问题。后续若需要让临时插入节点也支持 `random_event`，应作为独立扩展变更处理，而不是在本次最小实现中顺带加入。
