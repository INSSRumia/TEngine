# 战斗系统设计

本文档描述当前 Combat 域的核心职责、数据边界和与远征系统的衔接方式。项目内统一使用 `Combat` 表示战斗域，避免和 `Battle*` 形成并行命名。

## 1. Combat 域职责

Combat 域负责一场实际战斗中的实体创建、敌我判断、能力执行、碰撞结算、出生场地和结果输出。

Combat 域不负责：

- 远征路线推进
- 远征事件选项
- 远征 money、节点记录、环境切换
- 局外长期存档

这些内容由远征或更高层系统持有。Combat 结束后只通过结果数据把 Marble 状态和胜负摘要交还给调用方。

## 2. 主要模块

### 2.1 Marble

`Marble` 是战斗主体，继承能力系统基类，运行时数据保存在 `MarbleRuntimeData`。

关键数据：

- `InstId`：运行时 Marble 实例 Id
- `Config`：由 Marble 配置读取出的静态战斗参数
- `State`：当前 HP、护盾、经验、死亡状态等会随战斗变化的数据
- `Frame`：逐帧临时计算数据
- `CampConfigId`：配置阵营 Id，用于外观、颜色等身份信息
- `CombatSide`：战斗内敌我归属

`CampConfigId` 和 `CombatSide` 必须分开理解。一个敌方编队可以包含多个配置阵营的 Marble，但在当前战斗中它们仍属于敌方 `CombatSide`。

### 2.2 Equipment

`Equipment` 附着在 Marble 上，负责承伤、武器攻击、碰撞攻击、远程发射等能力。

装备通过 Factory 装配，核心骨架能力固定挂载，玩法扩展能力由 Luban 配置列表驱动。

### 2.3 Projectile

发射物是远程攻击的核心载体，独立于 Marble 生命周期管理，通过 Ability 组合实现不同效果。

关键约定：

- `Projectile` 不注册到 `CombatManager`
- `ProjectileFactory` 根据配置创建发射物
- `ProjectileRuntimeData.SourceCombatSide` 记录发射来源的战斗归属
- 命中时通过目标 Marble 或装备所属 Marble 的 `CombatSide` 做敌我判断
- 使用 HashSet 记录已命中目标以支持穿透

追踪模式：

- `None`：直线飞行
- `Target`：追踪目标 Marble
- `Point`：追踪固定坐标点

### 2.4 Battlefield

`Battlefield` 是 Combat 域的作战场地组件，挂在场地 prefab 上。

职责：

- 配置玩家方和敌方 Marble 的出生 `Bounds`
- 用 Gizmos 显示出生区域
- 根据传入的 `CombatSide` 选择出生区域
- 在对应 Bounds 内随机取点并摆放 Marble

`BattlefieldFactory` 负责根据 `CombatBattlefieldConfig` 创建场地。配置只提供 `battlefield_config_id`，实际 prefab 通过固定目录和同名规则加载：

`Assets/AssetRaw/Actor/Prefabs/Battlefield/{battlefield_config_id}`

如果找不到配置、prefab 或 prefab 缺少 `Battlefield` 组件，Combat 层应输出清晰错误并中止本场会话准备。

## 3. Factory 装配规则

Factory 负责“实例化 + RuntimeData 初始化 + 固定骨架能力挂载 + 配置扩展能力挂载”。

统一顺序：

1. 创建 GameObject / 组件
2. 初始化 RuntimeData
3. 写入 Config、State、Frame 等黑板区域
4. 挂载固定核心能力
5. 挂载配置驱动的 `lst_ability`
6. 完成必要的模块注册

不要在 Ability 内反推配置来源。新增玩法时优先判断它属于固定骨架字段，还是属于配置驱动扩展能力。

## 4. 敌我判断

Combat 内统一使用 `CombatSide` 判断敌我。

规则：

- 相同 `CombatSide` 视为友方
- 不同 `CombatSide` 视为敌方
- Projectile 使用 `SourceCombatSide` 和命中目标的 `CombatSide` 比较
- Equipment 碰撞攻击通过所属 Marble 的 `CombatSide` 比较

`camp_config_id` 不参与敌我判断，它只代表配置阵营。

## 5. 核心结算链路

### 5.1 伤害

当前伤害流程由能力链驱动：

1. `IReceiveDamage` 接收基础伤害
2. 触发接收后扩展点
3. 计算最终伤害
4. 触发计算后扩展点
5. 应用护盾或 HP 扣减
6. 触发应用后扩展点
7. HP 小于等于 0 时触发死亡能力

核心字段包括：

- `BasePendingDamage`
- `DamageAddition`
- `DamageMultiplier`
- `FinalDamage`
- `Defense`
- `Hp`
- `Shield`

### 5.2 治疗与护盾

治疗和护盾使用与伤害类似的接收、计算、应用三段式管线。

治疗结果不会超过 MaxHp，护盾结果不会超过 MaxShield。满血、满盾等状态由对应能力维护 Tag 或状态标记。

### 5.3 死亡

死亡能力负责设置死亡状态并触发死亡后扩展点。远征侧不能绕过 Combat 直接推断死亡结果，必须等待 Combat 输出结果包。

## 6. FixedUpdate 能力

核心 FixedUpdate 能力包括：

- 移动能力：根据 `MoveSpeed`、`Acceleration`、`TargetDir` 推动刚体
- 旋转能力：根据 `RotateSpeed`、`AngularAcceleration`、`RotateDir` 施加扭矩
- 索敌能力：通过 Combat 管理器获取最近敌人
- 行为逻辑能力：通过修改移动和旋转黑板字段实现近战、远程、冲刺、逃跑等行为

能力可以被动态添加和移除，但新增能力应遵循现有 Ability 生命周期和优先级规则。

## 7. 远征 Combat 会话

远征进入 Combat 节点时，会创建 `CombatSessionRequest`。

请求包含：

- `CombatSessionInstId`
- `NodeConfigId`
- `CombatEncounterConfigId`
- `BattlefieldConfigId`
- 玩家方 Marble 列表
- 敌方 MarbleSpawnConfig 列表

`ExpeditionCombatSessionController` 接收请求后：

1. 调用 `BattlefieldFactory.CreateBattlefield` 创建场地
2. 创建玩家 Marble 和敌方 Marble
3. 根据 `CombatSide` 调用 `Battlefield.PlaceMarble`
4. 开始 Combat 会话
5. 结束后生成 `CombatSessionResult`

Combat 会话结果是远征结算的唯一来源。远征根据结果更新局内 Marble 状态、执行胜负 Effect，并记录节点摘要。

## 8. 配置边界

Combat 相关 schema 位于 `Configs/GameConfig/Defines/` 下的多个文件中。

当前和 Combat 直接相关的配置包括：

- `marble.xml`：Marble 等级、固定骨架能力和扩展能力入口
- `equip.xml`：装备结构与装备能力
- `projectile.xml`：发射物结构与发射物能力
- `battlefield.xml`：Combat 场地配置

远征可以引用 Combat 配置 Id，但不应承担 Combat 配置解析和 prefab 创建职责。以 Battlefield 为例，远征只传递 `BattlefieldConfigId`，Combat 层通过 `BattlefieldFactory` 解析和实例化。
