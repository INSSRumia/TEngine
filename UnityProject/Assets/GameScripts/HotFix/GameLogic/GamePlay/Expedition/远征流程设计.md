# 远征最小循环设计

本文档描述当前 `add-minimal-expedition-loop` change 在代码中的实际落地方式，供 AI 与开发者快速理解远征最小闭环。

## 1. 范围

当前版本只实现最小循环：

`Entry -> EventNode -> CombatNode -> Settlement -> Entry`

明确不在本轮内实现：

- 完整家园玩法
- 撤退流程
- 多分支路线
- 配置表驱动的远征内容
- 磁盘落盘存档

## 2. 术语约定

- 统一使用 `Combat` 表示战斗域，不再引入并行的 `Battle*` 命名
- `Node` 指远征路线上的单个推进单元
- 首版仅保留两类节点：
  - `EventNode`
  - `CombatNode`
- `ExpeditionNodeRecord` 表示“某个节点本次运行后的执行记录”

## 3. 运行时数据边界

### 3.1 局外层

- `MarblePersistentData`
  - 局外持久化数据
  - 保存 Marble 的 ConfigId、等级、生命、经验、死亡状态
- `ExpeditionPersistentDataStore`
  - 当前阶段的运行期入口数据容器
  - 保存局外 Marble 列表、晶体数量和上次远征结果

### 3.2 远征层

- `MarblePersistentDataSnapshot`
  - 远征开始时从局外 Marble 深拷贝出的快照
  - 事件和 Combat 只修改快照，不直接改持久化数据
- `ExpeditionRunState`
  - 一次远征的总状态
  - 保存当前节点索引、路线定义、节点记录、Marble 快照、累计收益、结束原因
- `ExpeditionNodeRecord`
  - 记录单节点的选择结果、收益和 Combat 结果

### 3.3 Combat 边界

- `CombatSessionRequest`
  - 远征传给 Combat 的输入数据包
- `CombatSessionResult`
  - Combat 返回给远征的唯一结算来源
- 远征层不直接读取 Combat 场景对象来做结算

## 4. FSM 设计

`ExpeditionFlowController` 是远征流程 owner，使用 TEngine FSM 驱动。

状态集合：

- `ExpeditionFlowStatePrepare`
- `ExpeditionFlowStateEnterNode`
- `ExpeditionFlowStateEvent`
- `ExpeditionFlowStateCombat`
- `ExpeditionFlowStateApplyNodeResult`
- `ExpeditionFlowStateSettlement`
- `ExpeditionFlowStateFinished`

状态迁移规则：

- 只有 `ExpeditionFlowController` 能接收事件选择和 Combat 结果
- UI 只提交输入，不直接跳状态
- Combat 结果到达后，先回写 `ExpeditionNodeRecord` 和 Marble 快照，再决定是否进入结算

## 5. UI 约束

远征相关 UI 必须遵循 TEngine `UIWindow/UIModule` 流程：

- `ExpeditionMainUI`
  - 同时承担入口与出征准备
- `EventCardUI`
  - 承担事件节点输入
- `ExpeditionResultUI`
  - 承担远征结果展示

当前阶段只做功能型 UI，不等待美术资源。

为了避免额外 Unity 资源改动，本轮 UI 复用现有可加载 Prefab 作为窗口容器，并在 `ScriptGenerator` 中动态创建功能节点。这样仍然符合：

- `UIWindow` 生命周期
- `UIModule` 打开/关闭方式
- 节点命名规范

## 6. Unity MCP 约束

用户要求：一旦需要创建或修改 Unity 场景、Prefab、Canvas 层级或组件挂载，必须通过 Unity MCP 完成。

本轮实现没有新增或修改 Unity 资源文件，而是通过窗口脚本动态创建功能型节点，因此没有触发 Unity 资源侧改动。

如果后续要把功能型 UI 替换成正式 Prefab，请遵循：

1. 优先通过 Unity MCP 创建/修改 Prefab
2. 再更新 `ScriptGenerator` 绑定逻辑
3. 保持 `UIWindow/UIModule` 接入方式不变

## 7. 调试入口

- `GameApp` 在加载 `Test` 场景后直接打开 `ExpeditionMainUI`
- `ExpeditionMainUI` 中保留 `Combat 调试后门`
- 调试后门不会回写远征持久化数据，只用于快速起一场 Combat

## 8. 后续扩展建议

当最小循环稳定后，建议按以下顺序扩展：

1. 把最小路线从代码写死迁移到静态配置
2. 增加更多 `EventNode`
3. 增加路线分支和更多 `CombatNode`
4. 补真正的磁盘存档
5. 用 Unity MCP 把当前功能型 UI 换成正式 Prefab
